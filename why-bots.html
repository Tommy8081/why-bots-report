为什么我用 Bot 团队

从"一个模型派生多个子任务"到"多个 Bot 各用各的模型"
AI Agent 进展汇报
2026-11-20
1过去 · DSH Agent Team

一个模型，派生多个子 Agent

分工靠 prompt，不靠模型
  • 主 Agent 派生子任务，继承同一个模型
  • 调研、实现、评审都出自同一套判断
  • 模型换不了，任务拆得再细也是同源
问题：球员和裁判是同一个人，评审容易自证，盲区照旧。
2现在 · DS Bot

每个 Bot 一个模型、一份记忆

分工靠"谁是谁"，不靠提示词
  • Bot 之间模型可以不同，也能各自绑定工作目录
  • 主 Bot 只管调度与裁决，不亲自下场
  • 调研 / 实现 / 评审用不同模型，交叉验证
  • 谁做的、谁审的，记录里看得清清楚楚
结果：判断和执行被拆开，异源评审才有意义。
3趋势 · Bot 化

Agent 正在变成"在岗的同事"

从一次性对话，到长期角色
  • 行业里 Bot 化的方向已经很明确
  • 每个 Bot 有名字、职责、长期记忆
  • 人负责目标，Bot 团队负责推进
这也是我换到这套东西的外部理由：方向对，不是玩具。

每个 Bot 独立模型、独立记忆
谁做的、谁审的，一眼分清
同一个问题，出两版再选研究 Bot 和评审 Bot 用不同模型，结论不一致的地方就是风险点。
评审不共用实现方的模型盲区不重叠，评审才不是走流程。
长任务各管一段记忆、工作目录分开，不会互相污染上下文。
一句话
把判断和执行交给不同模型，是这套东西能真正上生产的原因。
